# 开题报告章节规划：项目设计与实现、系统测试

## 使用说明
- 本文用于补齐开题报告中“项目设计与实现”和“系统测试”两个章节。
- 结构按“可直接成文”方式组织：每节包含写作目标、建议内容、图表建议、量化指标、可复用模板。
- 你可以按本文顺序逐段扩写，也可将模板句替换为你的真实实验结果后直接使用。

## 第四章 项目设计与实现（规划）

### 4.1 章节目标与写作边界
- 目标：说明系统是如何从需求落地为可运行原型的，突出技术路线合理性与工程可实现性。
- 边界：本章聚焦“怎么设计、怎么实现”，不展开最终效果对比（放到测试章）。

可写模板：
本章围绕高血压知识图谱问答系统的工程落地过程展开，重点介绍系统总体架构、核心模块设计、关键流程实现与关键技术细节。通过本章说明所选技术方案能够支撑系统在医学问答场景下的准确性、可解释性与可扩展性需求。

### 4.2 需求分析与设计原则

#### 4.2.1 功能需求
- 用户问答：支持自然语言提问、多轮会话、流式回复。
- 知识检索：支持知识图谱检索、向量检索和混合检索。
- 文档处理：支持医学文档解析、分块、向量化与入库。
- 管理能力：支持图谱管理、会话管理、系统状态监控。

#### 4.2.2 非功能需求
- 准确性：回答尽量基于已检索证据。
- 可解释性：回答中体现检索依据和推理路径。
- 稳定性：核心依赖异常时具备降级提示与状态可观测。
- 可扩展性：模块解耦，便于后续替换模型与数据库。

#### 4.2.3 设计原则
- 分层解耦：数据层、检索层、编排层、服务层、前端层分离。
- 证据优先：先检索证据，再组织回答，降低幻觉风险。
- 工程可维护：统一配置、统一日志、统一接口风格。

### 4.3 系统总体架构设计

#### 4.3.1 架构概览
建议按“前端 + 后端 + Agent编排 + 图谱库 + 向量库 + 文档处理 + 模型服务”描述。

建议写作点：
- 前端：React 页面负责提问交互、会话管理、后台管理展示。
- 后端：FastAPI 提供问答接口、管理接口、健康检查接口。
- 智能体编排：基于 LangGraph/Agent 流程组织意图识别、检索、答案生成。
- 数据底座：Neo4j 存储结构化医学知识，Milvus 存储文本向量。
- 文档流水线：Docling 解析 + 分块 + 向量化 + 入库。

建议图表：
- 图4-1 系统总体架构图（建议用分层框图）。

可写模板：
系统采用“前后端分离 + Agentic RAG”架构。前端负责人机交互，后端负责流程编排与服务治理，知识层由 Neo4j 与 Milvus 组成双库协同的数据底座，实现结构化知识检索与语义检索的互补。

#### 4.3.2 数据流与控制流
- 数据流：用户问题 -> 问题理解 -> 检索 -> 证据融合 -> 回答生成 -> 前端展示。
- 控制流：会话状态维护、超时与异常处理、readiness 分级。

#### 4.4.3 Agent 编排与推理控制模块

- 说明多跳问题如何通过“拆分-检索-汇总”机制处理。

#### 4.4.4 文档解析与知识入库模块

- OCR 文字可用率（可按抽样人工标注）。
- 入库吞吐（篇/分钟、chunk/分钟）。

#### 4.4.5 后台管理与可观测模块

- 管理端能力：会话追踪、图谱管理、文档处理状态查看。

## 第五章 系统测试（规划）

### 5.1 章节目标与测试思路
- 目标：验证系统在真实医学问答场景下的功能正确性、性能、稳定性与实用性。
- 思路：采用“离线评测 + 在线接口测试 + 人工抽检”的组合策略。

可写模板：
本章通过功能测试、性能测试、鲁棒性测试与问答质量评测，对系统进行多维验证，重点检验系统在高血压领域问题上的回答质量与工程可用性。

### 5.2 测试环境与测试对象

#### 5.2.1 环境配置
- 软件环境：Python、FastAPI、Neo4j、Milvus、前端运行环境。
- 硬件环境：CPU/GPU、内存、磁盘（按你实际设备填写）。

建议图表：
- 表5-1 测试环境配置表。

#### 5.2.2 测试对象范围
- 问答主流程。
- 文档解析流程。
- 图谱与向量检索流程。
- 管理后台关键功能。

### 5.3 测试数据集设计

#### 5.3.1 领域问答基准集
- 可直接使用已有高血压指南问题集（30题）作为基础评测。
- 题型覆盖：诊断分级、风险评估、药物治疗、特殊人群、并发症等。

#### 5.3.2 复杂推理评测集
- 可使用 skill 评测问题集（40题），覆盖：
- LONG_TAIL（长尾问题）
- MULTI_HOP（多跳推理）
- SUB_QUERY（子问题拆解）
- CONFLICT（冲突证据处理）

#### 5.3.3 测试数据标注方式
- 客观题：用关键词覆盖率与事实一致性评分。
- 主观题：采用 3 维评分（准确性、完整性、可解释性）。

### 5.4 功能测试

#### 5.4.1 问答功能测试
测试项建议：
- 单轮问答是否返回有效答案。
- 多轮上下文是否正确继承。
- 流式输出是否正常。

#### 5.4.2 检索链路测试
测试项建议：
- 图谱检索可达性与结果结构正确性。
- 向量检索 Top-K 返回稳定性。
- 混合检索在复杂问题下的召回完整性。

#### 5.4.3 文档处理测试
测试项建议：
- PDF 解析正确率。
- OCR 结果可读性。
- 分块后语义完整性。

#### 5.4.4 管理端功能测试
测试项建议：
- 会话列表、图谱管理、文档处理页面功能完整性。
- readiness 状态展示与刷新逻辑正确性。

- 并发 1/5/10/20 用户。
- 问题长度短/中/长三档。
- 简单事实问题与复杂推理问题分开统计。

### 5.6 鲁棒性与异常场景测试

#### 5.6.1 依赖异常测试
- Neo4j 不可用时行为。
- Milvus 不可用时行为。
- 模型服务超时或报错时行为。

#### 5.6.2 输入异常测试
- 超长输入。
- 非医学闲聊输入。
- 含歧义或矛盾描述的问题。

验收标准建议：
- 系统不崩溃。
- 返回可解释提示。
- 日志可定位问题。

### 5.7 问答质量评测与结果分析

#### 5.7.1 自动化评测
- 使用 LangSmith 评测脚本对运行日志进行批量评分。
- 输出指标：平均分、评分分布、低质量样本比例。

#### 5.7.2 人工评审
- 由医学背景评审者抽样复核。
- 记录“事实错误、过度推断、证据缺失、表达不清”四类问题。

#### 5.7.3 结果展示建议
- 总体正确率与分题型正确率。
- 长尾/多跳问题与普通问题对比。
- 典型成功案例与失败案例分析。

### 5.8 问题分析与优化策略
- 问题1：证据召回不充分 -> 优化检索策略、扩展知识库覆盖。
- 问题2：多跳推理链断裂 -> 改进子问题拆分与证据融合逻辑。
- 问题3：回答冗长或不稳定 -> 优化提示词模板与输出约束。

可写模板：
测试结果表明，系统在常规事实问答场景表现稳定，但在长尾问题和多跳问题上仍存在证据不足与推理链不完整现象。后续将通过优化检索召回、增强证据评估和调整回答约束策略持续改进。

### 5.9 本章小结（建议）
可写模板：
本章从功能、性能、鲁棒性和问答质量四个维度验证了系统可用性。测试结果说明系统已具备高血压领域智能问答原型能力，同时也识别出复杂问题场景下的改进方向，为下一阶段优化提供依据。
